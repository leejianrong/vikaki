Vikaki 0.1.0 is the first release: an engine that animates a cartoon (VRM) avatar from text or a microphone and delivers it to a local page, a browser meeting, an MJPEG feed, or a game's page, driven by a program or an LLM. This release is for projects that want to run Vikaki beside them without cloning it.

## Get it

```bash
docker run --rm -p 127.0.0.1:8787:8787 ghcr.io/leejianrong/vikaki:0.1.0          # hub, avatar page, test-tone voice; amd64 and arm64
docker run --rm -p 127.0.0.1:8787:8787 ghcr.io/leejianrong/vikaki:0.1.0-kokoro   # the same with the real voice (about 1.3 GB, amd64)
pip install https://github.com/leejianrong/vikaki/releases/download/v0.1.0/vikaki_client-0.1.0-py3-none-any.whl
```

The image and the Python client (`vikaki-client 0.1.0`) have the same version. Both images are signed (cosign, keyless) and carry an SBOM, also attached to this release: how to verify them is in [docs/release.md](https://github.com/leejianrong/vikaki/blob/v0.1.0/docs/release.md).

## What you can rely on

`protocol_version` is `1` and only grows by adding. Within version 1 nothing is renamed, removed or changed in meaning; a break waits for 2.0 and is announced here first.

- **The WebSocket protocol** ([protocol.md](https://github.com/leejianrong/vikaki/blob/v0.1.0/docs/protocol.md)): `hello` and `welcome` (a driver reads `welcome.protocol_version`), `utterance`, `cancel`, `turn_started` and `turn_ended`, `react`, `thought`, `table_state`, `transport_state`, and the speech events back.
- **The embed messages** ([embed.md](https://github.com/leejianrong/vikaki/blob/v0.1.0/docs/embed.md#stability-what-a-game-can-rely-on-vik-132)). Page to host: `audio_locked`, `audio_unlocked`, `speech_started`, `speech_finished`, `speech_interrupted`. Host to page: `unlock`, `audio_status`, `human_utterance`. A message list is pinned by a test.
- **The personas file** ([personas.md](https://github.com/leejianrong/vikaki/blob/v0.1.0/docs/personas.md#what-a-game-can-rely-on-vik-131)): format `version: 1`, mounted at `/data`, bundled avatars at `/app/avatars/`.
- **Configuration**: `VIKAKI_TTS`, `VIKAKI_TOKEN`, `VIKAKI_FRAME_ANCESTORS`, `VIKAKI_PERSONAS`, `VIKAKI_ALLOWED_HOSTS` (a flag wins), and `--allow-host` for a hub behind a container network. The Host check stays on for every name not listed.
- **The Python client**: `vikaki-client 0.1.0` speaks `protocol_version` 1; any hub of protocol 1 works with any 0.x client.

## What is in it

- Avatars, seven emotions, personas, lip sync from the microphone and from text; a local voice (Kokoro, Apache-2.0) or a test tone.
- A CLI (`vikaki say`, `cancel`, `replay`, `serve`, `stream`), an MCP server, and the Python client for games.
- A table view for several seats, with a spectator panel, cameras, sound effects and a cozy den: the poker example in `examples/poker` is the first game built on it (it is an example, not part of the promise above).
- Docker images, a compose example of a game beside the hub (`examples/compose`), and this release pipeline.

## Known limits

- The browser-meeting extension has been tested against a stand-in page, not a real call. Firefox and Safari are untested for the embed's sound handshake (the in-frame "Click for sound" button is the fallback).
- The image speaks with a steady test tone unless you use the `-kokoro` image; the real voice is CPU-bound and about a second to first audio.
- The `vikaki-render` image (Chromium, for `stream`) is built in CI but not published.
- The Wavelength team asked for this release (VIK-E11); changes from their first use will come as 0.1.x.
